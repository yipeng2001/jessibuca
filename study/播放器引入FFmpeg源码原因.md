🧠  **FFmpeg 的核心价值**

FFmpeg 是一个开源且功能异常强大的音视频处理库，被誉为音视频领域的“瑞士军刀”。Jessibuca 引入其源码主要是利用它：

*   **强大的解码能力**：FFmpeg 提供了对**海量音视频编码格式**（Codec）和**容器格式**（Container）的支持。这意味着 Jessibuca 可以解码不仅仅是 H.265，还包括其他许多浏览器不原生支持的格式。
*   **统一的处理框架**：FFmpeg 提供了完整的解复用（Demux）、解码（Decode）流程。Jessibuca 可以通过调用 FFmpeg 的接口，直接处理如 FLV、MP4 等容器中的 H.265 视频流，从中提取出压缩的视频数据（Packet），然后将其解码为原始的图像数据（Frame）。
*   **高度的可定制性**：直接使用 FFmpeg 源码意味着开发者可以根据 Jessibuca 的具体需求进行**裁剪和定制**。例如，可以只编译 H.264、H.265 和 AAC 等必要的解码器，**显著减少最终生成的 Wasm 文件体积**。搜索结果提到，Jessibuca 通过裁剪优化，将 Wasm 体积控制在了约 1.2MB。

⚙️  **关键技术：WebAssembly (Wasm)**

浏览器本身并不能直接运行 C/C++ 代码（FFmpeg 由 C/C++ 编写）。Jessibuca 通过 **Emscripten** 工具将 FFmpeg 源码**编译成 WebAssembly (Wasm)** 格式。

*   **高性能**：Wasm 是一种低级的二进制格式，可以在现代浏览器中以接近原生的速度运行，这使得在浏览器中进行高效的软解码成为可能。
*   **跨浏览器兼容**：几乎所有现代浏览器都支持 Wasm。因此，一旦 FFmpeg 被编译成 Wasm，Jessibuca 就能在**包括 PC、手机、微信等在内的多种平台和环境**中实现一致的解码能力，无需插件。

🧱  **Jessibuca 的工作流程简析**

Jessibuca 播放器结合 FFmpeg 和 WebAssembly 后，其核心解码流程大致如下：

1.  **获取数据**：通过网络（例如使用 `fetch` 或 WebSocket）获取音视频流数据（如 HTTP-FLV 流）。
2.  **传输至 Worker**：将接收到的流数据（通常是 `ArrayBuffer` 形式）通过 `postMessage` 传递给运行在 Web Worker 中的 Jessibuca 解码模块。
3.  **Wasm 解码**：在 Web Worker 中，**由 FFmpeg 编译而来的 Wasm 模块**接手工作。
    *   它调用 FFmpeg 的函数解析流数据（例如使用 `av_parser_parse2` 解析出数据包）。
    *   然后调用相应的解码器（如 HEVC 解码器）将压缩的视频数据包解码成原始的 YUV 帧数据。
4.  **回调与渲染**：Wasm 模块通过预设的回调函数将解码后的原始视频帧数据（YUV）返回给 JavaScript。
5.  **画面绘制**：Jessibuca 最终将这些 YUV 数据通过 **WebGL** 绘制到 `Canvas` 元素上呈现给用户，或者在某些配置下使用 `Video` 标签。
